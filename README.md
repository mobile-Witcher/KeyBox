## 1. 这是什么

**KeyBox 是给 20 人以内的团队用的密钥保管箱：每人用自己的主密码（本地加密密码）在本机加密自己的 API 网址与密钥，云端和管理员都只能看到密文（乱码）。**

| 项 | 说明 |
|---|------|
| 给谁用 | 需要把 API 网址与密钥分给若干人各自保管的小团队 |
| 规模上限 | **20 人**。不做分页、不做配额、不做限流 |
| 有哪两种人 | **终端用户**：存自己的密钥。**管理员**：发邀请码、管账号 |
| 交付形态 | 桌面端 Windows exe；安卓端 apk |
| 后端 | 腾讯云开发 CloudBase（提供数据表、登录、云函数） |
| 许可证 | MIT，版权持有人「机动战士」 |

## 2. 隐私声明（最重要的一节，请先读完）

| 承诺 | 含义 |
|------|------|
| 云端只有密文 | 密钥在你的电脑上加密后才上传。云端存的是乱码，**包括数据库管理员在内，在后台直接看表也看不到明文** |
| 管理员也读不到 | 管理员只能**停用账号**和**删除数据**，没有任何"查看密钥"的入口 |
| 用户之间互不可见 | 每人只能读写自己的记录，看不到别人的任何东西 |
| 主密码不出本机 | 主密码只在你的电脑上参与计算，**永远不会上传**，也没有任何找回途径 |
| 密钥明文不出本机 | 密钥明文只在你的电脑内存里出现，不写日志、不进任何上报 |

> **一句话**：这个产品的设计目标是"连运营它的人都读不到你的密钥"。代价见下一节。

## 3. 代价（读之前必须知道）

这个产品把"别人读不到你的密钥"放在第一位，代价是**没有人能帮你兜底**。分三层：

### 第一层：主密码只在你本机

主密码只在你的电脑上参与计算，**云端没有、管理员也看不到**。正因如此，我们（以及平台、管理员）**没法帮你找回密码**——不是不愿意，是手上根本没有能解开密文（乱码）的钥匙。

### 第二层：项目将提供两个自救手段，代价是它们得你自己保管

> **状态说明（请务必看完再往下读）**：下面这两样**目前尚未正式可用**。**在它们正式可用之前，主密码丢失仍然意味着数据不可恢复。**

| 自救手段 | 管什么用 | 代价 |
|---|---|---|
| **恢复码**（一次性自救码） | 忘了主密码时，用它在本机解开数据并**重设主密码** | **只显示一次**，你自己抄存。**丢了就等于没开** |
| **加密备份文件** | 换设备、设备坏了时，用主密码在本机还原全部数据 | 文件你自己保存。文件丢了，备份就没了 |

> 这两样东西**服务端不参与、不知晓**，所以也**不可能帮你找回**。

### 第三层：三者全丢，就真的没了

**主密码 + 恢复码 + 备份文件，三者全丢 = 永久不可恢复。**

| 会发生什么 | 你登录得进去，但所有密钥都是一片乱码，解不开 |
|---|---|
| 最后的补救 | 请管理员删除你的全部数据 → 管理员给你一个新的邀请码 → 你重新开户、重新录入密钥（**原有的密钥已经取不回来了**） |

> 这不是 bug，是设计取舍：任何"平台帮你找回"的方案，都必然要求平台或某处握有能解开密文的钥匙，那"管理员也读不到"就不成立了。

## 4. 两类人分别能做什么

| 角色 | 能做什么 | 不能做什么 |
|------|----------|------------|
| 终端用户 | 用邀请码自助开户；存/改/删自己的密钥；打标签；本地搜索；遮掩显示与一键复制 | 看不到任何别人的密钥；不能改自己的账号状态 |
| 管理员 | 生成/作废邀请码；看用户列表（用户名、条目数、状态、注册时间）；停用/启用账号；删除某用户的全部数据 | **读不到任何人的密钥**；看不到密钥内容；不能改用户主密码；**即便拿到用户的恢复码密文也解不开**，也没有任何代用户恢复的入口 |

## 6. 快速开始

### 6.1 你要准备什么

| # | 准备项 | 说明 |
|---|--------|------|
| 1 | 一个 CloudBase（腾讯云开发）环境 | 用来存数据与跑云函数。开通方式见第 7 节 |
| 2 | 本机 Node.js 环境 | 用来跑初始化脚本与打包 |
| 3 | 想好第一个管理员账号的用户名与密码 | **第一个管理员由你本人在初始化时手动输入**，之后一律走邀请码 |

### 6.2 安装与启动

| 步骤 | 命令 / 内容 | 说明 |
|------|------------|------|
| 1 | 把仓库放到本地任意目录 | 目录路径建议不含空格 |
| 2 | `npm install` | 安装依赖。**Windows 上若报错、或装完却跑不起来，见第 11 节** |
| 3 | `npm run dev` | 开发模式启动。按终端提示的地址打开浏览器（默认 `http://localhost:5173`） |
| 4 | `npm run build` | 生产打包，产物在 `dist/` 目录 |
| 5 | `npm test` | 跑一遍测试，用来确认环境装齐了 |
| 6 | 首次启动出现**初始化页**，手动输入第一个管理员账号 | 待实施确认后补齐 |

> **以上只列了已实际跑通的命令。** 没验证过的命令一律不写——例如桌面端打包命令见第 8 节，仍待补齐。

## 9. 本次不做（避免误解为"还没做"）

| 不做 | 原因 |
|------|------|
| 计费、订阅、配额售卖 | 20 人以内自用 |
| 多租户团队协作（共享密钥空间） | 与"用户之间互相看不到"的模型直接冲突 |
| 浏览器插件 | 不在既定交付端 |
| 自动登录目标网站、代用户调用 API | 一旦代发请求，密钥必须出本机，违反隐私承诺 |
| **平台侧**主密码找回：密保问题 / 邮件重置 / 客服申诉 | 云端没有主密码，做了就会破坏"别人读不到"的承诺。改为提供你自持的恢复码与加密备份导出，见第 3 节 |
| 管理员读取或导出用户明文 | 刻意砍掉的能力，不是遗漏 |
| 分页、限流、审计平台、埋点统计 | 20 人规模不需要，且埋点会诱发明文外流 |

## 10. 常见问题

| 问 | 答 |
|---|---|
| 我忘了主密码怎么办 | **平台帮不了你找回**（云端没有你的主密码）。项目**将提供**恢复码与本地加密备份作为自救手段（见第 3 节）。**在它们正式可用之前，主密码丢失就意味着数据不可恢复**，唯一的补救是让管理员删数据后重开、原有密钥取不回来 |
| 我忘了登录密码怎么办 | 请管理员处理（登录密码与主密码是两套，登录密码不影响已存密钥） |
| 管理员能看到我的密钥吗 | 不能。管理员只有停用和删除两个动作 |
| 管理员停用我之后会怎样 | 新登录被拒；你本机已解锁的内容会在约 1 分钟内被清空并强制登出 |
| 我能把密钥分享给同事吗 | 本次不做。请同事用自己的账号自行录入 |
| `npm install` 报错，或装完跑起来说"找不到模块" | Windows 上常见的环境坑，**不是项目代码问题**。补救命令与详细说明见第 11 节 |

## 11. 遇到问题？

本项目的排障手册是 **`docs/TROUBLESHOOTING.md`**，按「现象 → 原因 → 一条可整行复制的命令」写。**本文件不另写一份**，只做指路。

| 你遇到的情况 | 去哪看 |
|---|---|
| `npm install` 报错（`EBUSY`），或装完"成功"却报**找不到模块** | `docs/TROUBLESHOOTING.md` 问题 1。**快速补救**——在项目根目录整行复制执行：<br>`npm install --no-save @rollup/rollup-win32-x64-msvc@4.63.5 @esbuild/win32-x64@0.21.5` |
| 登录报"安全域名 / 域名未授权"，或云函数报环境变量缺失 | `docs/TROUBLESHOOTING.md` 问题 2 及其「卡在哪一步」速查表 |
| 改代码前想避开已知的坑（例如新增记录时归属列为空、谁都查不到也删不掉） | `docs/TROUBLESHOOTING.md` 问题 3（**改代码前必读**） |
| 管理员账号失联、进不去后台（忘了登录密码、账号被停用等） | `docs/RECOVERY.md`（灾备救援手册，逐步写清"打开哪里 → 点什么 → 出现什么算成功"，随附本地救援脚本 `scripts/rescue-admin.js`）。**注意边界**：它只能恢复"账号能登录"；**能不能解开你已存的密钥，只取决于你手上的主密码 / 恢复码 / 备份** |

> 为什么单列这条：`npm install` 那个坑是**平台与工具链层面的问题，不是本项目代码的问题**，但别人 fork 之后卡在这里很容易直接放弃——正是"开源部署可复现"要防的那种失败。
