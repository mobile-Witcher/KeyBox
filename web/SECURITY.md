# 安全政策（SECURITY）

## 安全模型（一句话）

KeyBox 是端到端加密的密钥保管箱：**明文只活在你的本机**，云端（含数据库后台）与管理员**都只能看到密文（乱码）**。

## 三道边界

| 层 | 名称 | 挡什么 |
|----|------|--------|
| ① | 本机（加密边界） | 主密码 → PBKDF2 派生主密钥 → AES-GCM 加解密，全部在本机内存完成；主密码与密钥明文**永不出本机** |
| ② | 云函数（权限边界） | 只看密文、只管身份（校验邀请码 / 管理员 / 归属），不接触明文 |
| ③ | 云数据库（GRANT + RLS 边界） | `kb_secrets` 只存密文 `payload`；归属列 `owner_id` 由数据库列默认值 `DEFAULT auth.uid()` 写入；行级安全策略（RLS）保证用户只能读写自己的行；`kb_users` / `kb_invites` 不向客户端授予任何权限 |

## 明确的安全承诺

- 云端任何位置（数据库表、日志、抓包）**不出现密钥明文**。
- 管理员**读不到**任何人的密钥内容，只有"停用账号"与"删除数据"两个动作。
- 主密码**没有平台侧找回途径**（云端根本没有主密码）；只提供用户自持的**恢复码**与**本地加密备份**。
- 归属标记由**数据库自己**写入（列默认值 `DEFAULT auth.uid()`），前端传值一律忽略。

## 已知边界与取舍（不是缺陷，是设计）

- 忘记主密码、且恢复码与备份文件全丢 = **永久不可恢复**。
- 未签名的安装包会被系统安全提示拦截（Windows SmartScreen / 安卓"未知来源"）。
- 停用账号后有两个收敛窗口：云端访问窗口约 ≤15 分钟（兜底 access_token 自然过期 2 小时）；"本机已解锁内容"窗口约 ≤1 分钟（客户端前台轮询发现停用即登出并清空内存主密钥）。

## 报告漏洞

请**不要**在公开 Issue 中披露可被利用的细节，改用私下通道：

- 邮件：`<待补齐：安全联系邮箱>`
- 或在仓库的 Security 页面使用 "Report a vulnerability"（私密通道）。

报告时请尽量附上：影响范围、复现步骤、最小复现（PoC）、你评估的严重级别。我们会在确认后尽快修复，并（在你同意时）于致谢中署名。

## 不在范围内

- 所依赖的第三方平台（腾讯云开发 CloudBase）自身的安全漏洞。
- 用户本机被恶意软件、键盘记录器等攻破导致的明文泄露。
- 社会工程学攻击、物理接触并解锁用户设备。

## 敏感信息纪律（给贡献者）

**请勿**在代码、注释、日志、测试用例、提交历史中写入：主密码、密钥明文、CloudBase 环境 ID、SecretId / SecretKey、自定义登录私钥、keystore 口令。

`.env*`（保留 `.env.example`）、`*.keystore`、`*.jks`、`tcb_custom_login.json` 已被 `.gitignore` 挡住；`.env.example` 只放键名不放真值。
